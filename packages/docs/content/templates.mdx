# Templates

`pf template` creates a new repo from a **template**: a data package `@pulpfixer/template-<name>` on cellars. pf installs the template's latest version every time it applies one, so a template changes with a version bump on the registry and needs no new pf. The templates are `query-package` (the starting point of a [query package](/plugins/writing-a-query-package)), `pipe-package` (a [pipe package](/plugins/writing-a-pipe-package)) and `io-adapter` (an [IO adapter add-on](/plugins/writing-an-io-adapter)).

```bash
pf template                                         # list templates: cached here and on the registry
pf template apply query-package revrec --driver mysql
pf template apply query-package revrec --connection billing --driver mysql --summary "Revenue recognition"
pf template apply query-package revrec --driver mysql --dry-run    # the file list, nothing written
pf template apply query-package revrec --driver mysql --dir ../query-revrec   # relative to this folder
pf template apply pipe-package orders --input db --output csv --connection billing
pf template apply io-adapter acme-api
```

In a terminal, pf asks for each value you did not pass, with its default filled in. Without one, it uses the defaults and stops with the usage line when a required value is missing, so scripts and agents pass flags.

## pf new

`pf new` is the shortcut for the three things you start most often. In a terminal it shows a menu (query package, pipe package, empty scratch); it prints the matching command so you can skip the menu next time.

```bash
pf new                      # the menu
pf new query revrec --driver mysql     # = pf template apply query-package revrec --driver mysql
pf new pipe orders --input db --output csv
pf new scratch try-1        # an empty repo ~/dev/try-1 (the repos folder, or --dir)
pf new scratch              # asks for a name, `scratch-<date>` by default
```

`query` and `pipe` hand every other argument to `pf template apply`, so they take the same flags. `scratch` creates the folder (it must not exist, or must be empty), runs `git init` unless it is already inside a git repo, runs `pf repo --no-deploy`, and prints `cd <the folder>`. It takes `--dir <path>`, `--dry-run`, `--no-git` and `--no-repo`. A scratch name is lowercase letters, digits and dashes. Without a terminal `pf new` prints its usage (exit 2) and `pf new scratch` needs a name.

## What apply does

1. Installs `@pulpfixer/template-<name>@latest` into `~/.pf/templates`. With `--offline`, or when the registry cannot be reached, it uses the copy fetched last time.
2. Fills the template's files with the values and writes them into the new folder: `<repos folder>/query-<name>/` for the query package (the repos folder is `~/dev` unless `pf suite config set reposDir <folder>` says otherwise, and pf creates it when it is missing), or `--dir` for another place. If any of the files already exists there, nothing is written.
3. Runs `git init` in the folder, unless it is already inside a git repo (`--no-git` skips this).
4. Runs `pf repo --no-deploy` on the new repo: the pf link, the pnpm commands, versioning and the background tone (`--no-repo` skips this).
5. Prints the next steps, starting with `cd <the new folder>`: the repo is not made in the folder you ran pf from, so the path is shown (`~/dev/query-revrec`).

A template is data. pf never runs anything from a template: the only commands are pf's own `git init` and `pf repo`.

| Flag | Meaning |
|------|---------|
| `--<param> <value>` | a template value (`--driver mysql`); the first one can also be given without its flag (`revrec`) |
| `--dir <path>` | where to create the repo instead of `<repos folder>/<template folder>`; relative to the folder you run pf in |
| `--dry-run` | list the files and the steps, write nothing |
| `--offline` | use the cached template, no registry |
| `--no-git`, `--no-repo` | skip `git init`, skip `pf repo` |

## The query-package template

`pf template apply query-package <name>` asks for:

| Value | Default | Meaning |
|-------|---------|---------|
| `name` | (required) | the command (`pf <name>`) and the package `@pulpfixer/query-<name>` |
| `--summary` | `Queries on the <name> database` | one line for the command list |
| `--connection` | `<name>` | the `pf db` connection the queries use |
| `--driver` | (required) | `postgres`, `mysql` or `sqlite` |

It creates a repo that builds, tests and publishes as it is:

| File | What |
|------|------|
| `src/index.ts` | `defineQueries({ ... })` with one `ping` query to replace |
| `tests/queries.test.ts` | a fake driver and a temporary pf home: tests check the SQL and the output, no database needed |
| `package.json` | `@pulpfixer/query-<name>`, depending on `@pulpfixer/plugin-db` and `@pulpfixer/kit` at the versions this pf ships; `build`, `typecheck`, `test` and `publish:cellars` (what `pf ps` runs) |
| `AGENTS.md` | the rules the coding agent follows when it writes the queries |
| `.npmrc` | the cellars registry, with `${NPM_TOKEN}` as the auth line |
| `pulpfixer.json`, `README.md`, `tsconfig*.json`, `.gitignore` | the rest |

Then:

```bash
cd ~/dev/query-revrec     # the folder pf printed
pnpm install
pf a "write the queries: monthly revenue per product, from these tables: ..."   # follows AGENTS.md and the query-package skill
pnpm test
pf ps            # publish to cellars, asks first
```

The agent uses the bundled `query-package` skill: it asks you for the schema (it has no database tools and never connects), writes each query with the `sql` template, adds a test per query, runs the checks, bumps the version, and leaves publishing to you.

## The pipe-package template

`pf template apply pipe-package <name>` creates a [pipe package](/plugins/writing-a-pipe-package) repo (`pipe-<name>/`, package `@pulpfixer/pipe-<name>`):

| Value | Default | Meaning |
|-------|---------|---------|
| `name` | (required) | the command (`pf <name>`) and the package name |
| `--summary` | `Pipes for <name>` | one line for the command list |
| `--input` | `db` | what the sample `copy` pipe reads: `db` or `csv` |
| `--output` | `csv` | what the sample pipe writes: `csv` or `db` |
| `--connection` | `<name>` | the `pf db` connection, when an end is a database |

It has `src/index.ts` (`definePipes` with the `copy` pipe to replace), `tests/pipes.test.ts` (memory adapter, fake driver and temp files, no database), `package.json` (depending on `plugin-io`, `plugin-db`, `plugin-csv` and `kit` at the versions this pf ships, and `publish:cellars`), `AGENTS.md` with the rules for the agent, the cellars `.npmrc`, and the rest. The agent side is the bundled `pipe-package` skill.

## The io-adapter template

`pf template apply io-adapter <name>` creates an [IO adapter add-on](/plugins/writing-an-io-adapter) repo (`io-<name>/`, package `@pulpfixer/io-<name>`):

| Value | Default | Meaning |
|-------|---------|---------|
| `name` | (required) | the adapter id, starting with a letter: lowercase letters, digits and dashes |
| `--summary` | `The <name> IO adapter for pf pipes` | one line for `pf io` |

It has `src/adapter.ts` (a working JSON Lines adapter to replace), `src/index.ts` (the plugin: `api: 3` and `ioAdapters`), `tests/adapter.test.ts` (contract, round trip, failed pipe, dry run), `package.json` (depending on `kit` only), `AGENTS.md`, the cellars `.npmrc` and the rest. The agent side is the bundled `io-adapter` skill.

## Writing a template

A template is a package `@pulpfixer/template-<name>` with two things in it:

- `template.json`: the summary, the default folder name, the values to ask for, files to rename, and the next steps.
- `files/`: the tree that is copied.

```json
{
  "summary": "A query package: @pulpfixer/query-<name>",
  "dir": "query-{{name}}",
  "params": {
    "name": { "prompt": "Query package name", "pattern": "[a-z0-9]+(-[a-z0-9]+)*" },
    "connection": { "prompt": "pf db connection it uses", "default": "{{name}}" },
    "driver": { "prompt": "Database", "choices": ["postgres", "mysql", "sqlite"] }
  },
  "rename": { "_package.json": "package.json", "_gitignore": ".gitignore", "_npmrc": ".npmrc" },
  "next": ["pnpm install", "pf ps"]
}
```

| Field | Meaning |
|-------|---------|
| `params` | the values, in order (the first one is positional). Each has a `prompt`, and optionally `help`, `default` (may use earlier values), `pattern` (the whole value must match) and `choices`. A value without a default is required |
| `dir` | the default folder name, one segment |
| `rename` | file names to rename when copying. npm drops or renames `.gitignore` and `.npmrc` on publish, and a nested `package.json` can change what npm packs, so ship them as `_gitignore`, `_npmrc`, `_package.json` |
| `next` | lines printed at the end |

In file contents, file names and `next`, `{{param}}` is a value and `{{version:@pulpfixer/<package>}}` is the version of a package bundled with the pf that applies the template (`@pulpfixer/kit`, `@pulpfixer/plugin-db`, `pulpfixer`, ...). An unknown placeholder stops the apply. Files with a NUL byte are copied as they are.

Values may not contain quotes, backslashes, backticks, `{{` or newlines, so they are safe inside JSON and TypeScript strings. File paths must stay inside the new folder: no `..`, no absolute paths, nothing under `.git`, no symlinks.

In this monorepo a template is `packages/template-<name>` (see `packages/template-query-package`), with an entry in `ORDER` in `scripts/release.mjs`. Like a preset it is published alone and core does not pin it: `pnpm ver bump packages/template-<name> minor`, then publish. Its `files/src` is part of `pnpm typecheck`, so a change in the query API that breaks the template fails the check.
