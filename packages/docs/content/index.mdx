# pf (pulpfixer)

`pf` is one command line for every repo, in any language. Run `pf` in a repo to get its menu, and use the same short commands everywhere: `pf dev`, `pf build`, `pf test`, `pf docs`, `pf ver`, `pf deploy staging`. pf works out what each one means in the repo you are in.

```bash
pf              # menu for this repo
pf dev          # run the app locally (any language)
pf docs         # run the repo's docs site
pf ver          # versions and bumps
pf agent        # a coding agent with pf's tools
```

Every invocation prints a banner with its version (`pf v4.39`) on **stderr**, so stdout stays pipeable.

## Install

```bash
[ -w "$(npm root -g)" ] || { mkdir -p ~/.npm-global && npm config set prefix ~/.npm-global && export PATH="$HOME/.npm-global/bin:$PATH" && echo 'export PATH="$HOME/.npm-global/bin:$PATH"' >> ~/.$(basename "$SHELL")rc; }; npm install -g pulpfixer --registry https://cellars.staging.pangenea.com/ && pf setup
```

Needs Node >= 18 and npm, no token, no `sudo` (a user-owned npm prefix is set up when the global directory is not writable). See [Getting started](/getting-started#install) for the other ways.

## Principles

- **No third-party runtime dependencies.** Colors, the picker and argument parsing are hand-written.
- **Dry runs.** Commands that run something support `--dry-run`.
- **Safe by default.** Production is never guessed, and always asks. The agent and MCP tools deploy to staging only.
- **No secrets in pf.** pf never reads, prints or writes a registry token. The agent never receives AWS credentials.
- **Works without a terminal.** Menus and prompts fall back to static output without a TTY, and colors follow `NO_COLOR` and `FORCE_COLOR`.
